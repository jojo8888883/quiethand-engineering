# 做成了什么，哪些地方还不行

这是已有工件的阶段总结，不是新实验。每个结果保留原证据身份。

## 已有成果

1. **真实 RGB-D 视频的多模型管线跑通。** 完整动作语义、手运动、物体区域/姿态可以生成，时间、坐标、来源和缺项可追溯。
2. **用户看过结果并给出修正。** 完整动作的 30 条 calibration 中，25 条被接受、5 条被拒绝并有文字修正。这里是一次直接查看的结果，不是独立测试集准确率。
3. **修复了一个真实接口问题。** 语义里的 tool/target 不再直接决定 CAD 身份；通过 `role_to_entity` 明确指定，避免碗/盘等配反。
4. **建立了定位误差来源的办法。** 同帧替换预测/参考手与物体，在一个案例中分离出“预测手本身就足以造成相对轨迹不稳定”。
5. **完成一次固定预算的质检排序比较。** 原规则和结果留在包内，可查原因和数字。

## 最新固定 30 条 evaluation

| 同样只查看 6 条 | 找到的核心 proxy 错误 | 未查看的 24 条中漏下的错误 |
| --- | ---: | ---: |
| VLM-only | 1 / 4 | 3 |
| VLM + 既有几何 | 2 / 4 | 2 |

错误目标来自一次 Codex 盲视查看，而非独立人类金标准。VLM 风险分数全部为零，实际按不透明 ID 打破并列。因此成立的是**这个固定样本里多选出一条 proxy 错误**，不是通用几何优势、降本、自动纠错或训练收益。

原始数字在 `records/evaluation_result.json`，最终可支持的说法在 `records/evaluation_claims.md`。前者保留了当时的简短结论字段，解释时须结合后者，不单独摘取宽泛措辞。

## 不成功的尝试也留下

| 尝试 / 现象 | 实际发现 | 以后怎么少走弯路 |
| --- | --- | --- |
| 太短的固定窗口 | 可能截到动作前后，被误判为没动作 | 先确认完整动作区间，再抽用于几何的时序帧 |
| 实体认对后再问主动/支撑 | 单例认对木砧板和木勺，但把黑色把手误当笔，左右角色仍判反 | 对象身份与任务角色分开检查；身份正确不保证语义正确 |
| 整段手物相对跨度当“漂移” | 真实操作也会改变相对位置 | 不把整段位移无条件归因于噪声 |
| 用手 mask 的深度统一平移手根 | 案例中左手部分改善，右手更差；两侧仍未满足原稳定条件 | 局部手腕/袖子表面不是完整手的中心，不能默认全轨迹这样修 |
| 结构化左右交换 | 得到 60 个视图，但独立样本仍为 30 个 | 不把字段增强当成新增真实数据或效果提升 |
| 更细的约束编译器 | 理想输入下数学与工程检查通过 | 真实接触和稳定几何输入没可靠闭合，不应输出确定的物理结论 |

单例角色失败原文在 `records/entity_semantic_binding_result.md`；手物误差归因数值在 `records/hand_stability_attribution.json`。其中图片字段只指向原工作区媒体，本包未包含那些图片。

## 阶段定位

最适合复用的是：数据接口、对齐经验、实体身份绑定、诊断方法、查看与反馈工具，以及接过模型的运行配方。

尚未做成的是：任意 RGB 视频的高精度三维恢复、可靠支撑角色/接触力标签、可直接交给某个 VLA 的完整训练数据集，以及机器人收益验证。换下游模型前，应先确定它真正读取哪些字段；不能假定标签越多越有用。
